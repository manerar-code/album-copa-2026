# ADR-004: Static HTML for Vercel /privacidade Privacy Policy Page

## Status

Accepted

## Date

2026-06-10

## Context

F4 requires publishing the Privacy Policy at a public URL on Vercel
(`album-copa-2026-sable.vercel.app/privacidade`) for use in App Store Connect and Google Play
Console. The Vercel deployment currently serves the Expo web build. Three approaches were
evaluated for adding a `/privacidade` route to the existing Vercel deployment.

## Decision

Create `web/public/privacidade.html` as a self-contained static HTML file. Vercel serves
files in the `public/` directory of the web build output as static routes, making
`/privacidade` accessible at `album-copa-2026-sable.vercel.app/privacidade` automatically
without any configuration changes.

The HTML file includes: app name, policy date, data collected, retention periods, LGPD rights
(access, correction, deletion, portability), contact email (manner@kbase.com.br), and a
link back to the app.

## Alternatives Considered

### Alternative B: Expo Web Route at /privacidade

- **Description**: Create a new screen `PrivacyPolicyScreen` routed at `/privacidade` in
  the Expo web build using `@react-navigation/native` or Expo Router
- **Pros**: Shares components (typography, colors) with the in-app screen; single source
  of truth for policy text
- **Cons**: Requires configuring web URL routing in React Navigation (non-trivial);
  risk of breaking the existing Expo web build; content is static — no benefit from dynamic
  rendering; increases bundle complexity
- **Why rejected**: Overengineered for static content; introduces regression risk to web build

### Alternative C: Vercel Serverless Function

- **Description**: `api/privacidade.ts` Edge/Serverless Function that returns HTML
- **Pros**: Programmatic, composable
- **Cons**: Requires a Vercel serverless function for completely static content;
  cold starts add latency; no benefit over static file
- **Why rejected**: Static file is the simplest correct solution for static content

## Consequences

### Positive

- Zero build-time impact — static files are served directly by Vercel's CDN
- No changes to `app.json`, `webpack.config.js`, or navigation setup
- URL is live immediately after next Vercel deployment
- File is version-controlled alongside app code — policy history is in git

### Negative

- Policy text exists in two places: `privacidade.html` (for the web URL) and the in-app
  `PrivacyPolicyScreen` component. Updates must be applied to both.
- HTML styling must be maintained separately from the app's design system

### Risks

- **Stale policy text**: If the policy is updated in-app but not in the HTML file.
  Mitigation: document both locations in a comment at the top of each file; include
  "Last updated: YYYY-MM-DD" in both.

## Implementation Notes

File path: `web/public/privacidade.html` (or `public/privacidade.html` at project root,
depending on Vercel output directory configuration in `vercel.json`).

Verify the Vercel `outputDirectory` setting — if Expo web outputs to `web-build/`, the
file should be placed in `web-build/privacidade.html` as part of the build step, or
a `vercel.json` rewrite can map `/privacidade` to the static file.

Recommended: check `vercel.json` or Vercel project settings for `outputDirectory`.
If absent, test by deploying a `public/privacidade.html` and verifying the route resolves.

```json
// vercel.json (if rewrite needed)
{
  "rewrites": [
    { "source": "/privacidade", "destination": "/privacidade.html" }
  ]
}
```
