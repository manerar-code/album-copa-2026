# ADR-003: Supabase Edge Function + Resend for Deletion Notification Emails

## Status

Accepted

## Date

2026-06-10

## Context

F5 requires sending two email notifications:
1. Confirmation email when the user requests account deletion
2. Reminder email 3 days before the 30-day grace period expires

The app has no existing email-sending infrastructure. Supabase provides built-in transactional
emails only for auth events (magic link, confirm, reset) — not for custom application events.
An email delivery mechanism must be chosen that integrates with Supabase Edge Functions and
requires minimal operational overhead for a solo-developer project.

## Decision

Use a **Supabase Edge Function** (Deno/TypeScript) to send emails via the **Resend API**
(free tier). Two functions are involved:

1. `send-deletion-confirmation` — triggered by the app client immediately after inserting a
   row into `account_deletion_requests`. Sends the confirmation email with account name,
   deletion date, and a cancellation deep-link.
2. `process-pending-deletions` — scheduled via Supabase cron (pg_cron or Edge Function
   scheduled job). Runs daily. Queries `account_deletion_requests` for:
   - Rows where `scheduled_delete_at <= now()` and `completed_at IS NULL` and
     `cancelled_at IS NULL` → execute permanent deletion
   - Rows where `scheduled_delete_at - interval '3 days' <= now()` and reminder not yet
     sent (`reminder_sent_at IS NULL`) → send reminder email, set `reminder_sent_at`

Resend free tier: 3,000 emails/month, 100 emails/day — sufficient for an indie app launch.
The `RESEND_API_KEY` is stored as a Supabase Edge Function secret (not in version control).

## Alternatives Considered

### Alternative B: Skip email notifications

- **Description**: No email sent. The LGPD compliance is achieved through the in-app grace
  period and cancellation flow alone.
- **Pros**: Zero new dependencies, zero external API calls, simplest implementation
- **Cons**: LGPD best-practice (and user expectation) is to confirm account deletion by email;
  the PRD explicitly requires email notification at request time and 3 days before deletion;
  without email reminder, users are more likely to lose their accounts accidentally
- **Why rejected**: PRD requirement (F5 behavior item 6) and user trust

### Alternative C: Supabase Auth built-in emails

- **Description**: Reuse Supabase's SMTP configuration (used for auth emails) by triggering
  a custom auth event template
- **Pros**: No new service integration
- **Cons**: Auth email templates are limited to specific auth events; there is no "custom
  application email" hook in Supabase Auth; achieving this requires hacking the welcome/
  confirm template which would break the auth email content
- **Why rejected**: Not designed for custom application emails; would corrupt auth email flow

## Consequences

### Positive

- Resend free tier covers projected send volume at launch (< 100 deletions/month expected)
- Edge Functions run server-side with the `service_role` key — can safely write to
  `account_deletion_requests` and delete from `user_collections`/`user_albums`/`auth.users`
- No additional npm package needed in the React Native app — email is sent from the server
- `RESEND_API_KEY` never touches the client bundle

### Negative

- Requires Resend account creation (free, ~2 minutes)
- `reminder_sent_at` column must be added to `account_deletion_requests`
- Supabase scheduled jobs (pg_cron) require enabling the pg_cron extension on the Supabase
  project — one-time setup via SQL editor
- Edge Functions require Deno runtime knowledge (differs from Node.js)

### Risks

- **Resend delivery failure**: Email not delivered due to spam filters or Resend API errors.
  Mitigation: retry logic in the Edge Function (max 3 retries with exponential back-off);
  deletion proceeds regardless of email delivery status — email failure is non-blocking for
  LGPD compliance.
- **pg_cron reliability**: Supabase-hosted pg_cron has occasional delays. Mitigation: the
  cleanup function runs daily; a 1-day delay in deletion is acceptable within the 30-day grace.

## Implementation Notes

```typescript
// supabase/functions/send-deletion-confirmation/index.ts
import { Resend } from 'resend';

const resend = new Resend(Deno.env.get('RESEND_API_KEY')!);

Deno.serve(async (req) => {
  const { email, userName, scheduledDeleteAt } = await req.json();
  const { error } = await resend.emails.send({
    from: 'noreply@album-copa-2026.app',
    to: email,
    subject: 'Sua conta será excluída em 30 dias — Álbum Copa 2026',
    html: deletionConfirmationTemplate(userName, scheduledDeleteAt),
  });
  return new Response(JSON.stringify({ ok: !error }));
});
```

Scheduled cleanup via pg_cron (daily at 2am UTC):
```sql
SELECT cron.schedule(
  'process-pending-deletions',
  '0 2 * * *',
  $$SELECT net.http_post(url := '<supabase-project-url>/functions/v1/process-pending-deletions',
    headers := '{"Authorization": "Bearer <service_role_key>"}') AS request_id$$
);
```
