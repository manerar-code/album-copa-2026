# ADR-003: Remove selecoes Parameter from parseTradeList

**Date:** 2026-06-16
**Status:** Accepted

## Context

`parseTradeList(text: string, selecoes: Selecao[]): ParseResult` accepts a `selecoes` parameter that has been unused since the allowlist gate was removed (the body immediately does `void selecoes;`). The parameter was kept at the time to avoid a breaking change. The Troca_Fig refactor rewrites all callers and all 37 tests, making this the right moment to clean up.

## Decision

Remove the `selecoes` parameter. New signature: `parseTradeList(text: string): ParseResult`. Update all callers (`TradesScreen.tsx`) and all 37 unit tests in `parseTradeList.test.ts`.

## Alternatives Considered

- **Keep the parameter (`void selecoes;`):** Avoids diff in test files but leaves dead code in the public API. Future readers will wonder why the parameter exists and whether removing it would break something.
- **Make optional (`selecoes?: Selecao[]`):** Middle ground, but optional parameters on pure utility functions suggest conditional behavior that doesn't exist here. More confusing than removing outright.

## Consequences

- `parseTradeList` API is clean; no misleading parameter.
- All 37 unit test call sites must be updated (mechanical change — remove the second argument).
- `TradesScreen.tsx` useMemo call site updated (one line).
- No behavioral change — the function's output is identical before and after.
