# ADR-002: Reactive Comparison via useMemo — No Debounce

**Date:** 2026-06-16
**Status:** Accepted

## Context

The redesigned TradesScreen must run `runComparison` automatically whenever `inputText` changes, without a "Comparar" button press. Three reactivity strategies were evaluated.

## Decision

Call `runComparison` inside a `useMemo` keyed on `inputText` (and the stable store references `selecoes`, `figurinhas`, `collection`). No debounce state, no `useEffect`, no extra `setTimeout`/`clearTimeout` machinery.

## Alternatives Considered

- **useEffect + useRef<setTimeout> + debouncedText state (same pattern as `useSearch.ts`):** Delays comparison 400 ms after the last keystroke. Adds three extra state variables (`timerRef`, `debouncedText`, and a setState call) for a benefit that only matters when the user types character-by-character. In Trocas, users paste text (one `onChange` event) rather than type; debounce buys nothing and adds complexity.
- **Custom `useTradeComparison(inputText)` hook:** Encapsulates the useMemo in a dedicated file. Adds a new abstraction with no concrete benefit — `runComparison` is already a pure function; the hook would be a thin wrapper around `useMemo`. Violates YAGNI.

## Consequences

- `runComparison` is a pure function called inside `useMemo`; it runs synchronously on every render where `inputText` changes.
- For typical paste sizes (≤ 200 entries against ≤ 900 figurinhas), the computation completes in < 5 ms — no perceptible lag.
- Component state is simplified: `viewState` and `result` useState are removed; the comparison result is derived, never stored.
- If future profiling reveals a performance issue with very large inputs, a debounce can be added as a targeted fix without changing the architecture.
