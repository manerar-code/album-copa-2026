# ADR-001: Tap-to-Increment + Badge-Tap-to-Reset Interaction for Duplicate Quantity

## Status

Accepted

## Date

2026-06-16

## Context

The current sticker status model is binary for duplicates: a sticker is either `duplicate` or not.
Collectors frequently have more than one copy of the same sticker and want to track the exact
count so they can share accurate trade lists. The interaction must be discoverable and consistent
with the existing single-tap cycle (`missing → owned → duplicate → missing`).

## Decision

Extend the tap cycle so that each tap on a card already in `duplicate` state increments the
quantity counter by one (×1 → ×2 → ×3 … no upper bound). The quantity badge displayed on the
card becomes an independent tap target that resets the sticker directly to `missing`. This
preserves the low-friction single-tap advance while giving collectors a clear escape hatch
without needing a new gesture type.

## Alternatives Considered

### Alternative B: Capped cycle at ×9

- **Description**: The cycle wraps back to `missing` automatically after ×9.
- **Pros**: No new tap target; fully predictable cycle length.
- **Cons**: Accidental tap at ×9 silently resets the card; limits collectors with many copies.
- **Why rejected**: Silent loss of data on accidental tap is a worse failure mode than an
  unlimited counter.

### Alternative C: Tap increments + long-press opens quantity picker

- **Description**: Long press shows a numeric selector (0–20) for direct input.
- **Pros**: Most precise; recovers any count in one gesture.
- **Cons**: Introduces a new gesture type (long press) not used elsewhere in the app, breaking
  interaction consistency.
- **Why rejected**: Interaction cost outweighs the precision benefit for the common case (1–5
  duplicates).

## Consequences

### Positive

- Zero friction for the most common case: one tap marks a sticker as ×1 duplicate.
- Consistent with existing tap-to-cycle model — no new gestures to learn.
- Badge tap provides a clear, visible reset target.
- No hard upper limit frustrates no one.

### Negative

- Users who tap past their intended count must tap the badge to reset, then re-tap to the
  correct count — slightly tedious for large corrections.
- The badge-tap-to-reset affordance must be clearly communicated on first use.

### Risks

- Risk: badge tap area is too small on small screens. Mitigation: ensure minimum touch target
  of 44×44 pt around the badge.
- Risk: accidental badge taps reset progress. Mitigation: badge tap resets to `missing` (not
  to `owned`), making the outcome obvious immediately.
