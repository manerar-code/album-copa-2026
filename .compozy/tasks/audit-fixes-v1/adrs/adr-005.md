# ADR-005: Logger Production Guard — __DEV__ on warn and error

## Status

Accepted

## Date

2026-06-08

## Context

`logger.ts` gates `logger.log` behind `__DEV__` but `logger.warn` and `logger.error` call `console.warn`/`console.error` unconditionally. In production builds these calls can expose PII (emails, tokens, error stack traces) in system logs accessible via Xcode Instruments, adb logcat, or third-party crash tools.

## Decision

Apply the same `__DEV__` guard to `logger.warn` and `logger.error`:

```typescript
warn: (...args: unknown[]) => { if (__DEV__) console.warn(...args); },
error: (...args: unknown[]) => { if (__DEV__) console.error(...args); },
```

Replace the direct `console.warn` call in `supabase.ts` with `logger.warn`.

## Alternatives Considered

### Alternative: Integrate Sentry SDK
- **Description**: Install `@sentry/react-native`, route `logger.error` to `Sentry.captureException`, apply PII scrubbing via `beforeSend`.
- **Pros**: Production error visibility, stack traces, user context, release tracking.
- **Cons**: New dependency (~500KB), requires Sentry project setup, DSN configuration, PII scrubbing rules. Out of scope for Phase 3 quick win.
- **Why rejected**: Valuable but out of scope for Phase 3. PRD explicitly excludes Sentry as optional.

### Alternative: Suppress + TODO comment
- **Description**: Apply `__DEV__` guard now, add `// TODO: integrate Sentry` comment.
- **Description**: Functionally identical to the chosen decision.
- **Why rejected**: Chosen approach is the same; explicit TODO is already implied by the PRD Open Questions.

## Consequences

### Positive
- No PII leaks in production builds via console output.
- Zero new dependencies.
- One-line change per method.

### Negative
- Production errors are no longer observable without a monitoring SDK.
- Silent failures in production harder to diagnose without Sentry.

### Risks
- Developers may rely on `logger.error` for debugging and be surprised by silence in production simulator builds if `__DEV__` is false. Ensure development builds use `__DEV__ = true` (default for Expo dev/preview profiles).
