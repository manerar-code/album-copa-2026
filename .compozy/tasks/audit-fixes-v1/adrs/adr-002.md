# ADR-002: expo-splash-screen with preventAutoHideAsync/hideAsync Pattern

## Status

Accepted

## Date

2026-06-08

## Context

The app shows a black screen on iOS TestFlight because the native splash screen is dismissed immediately by iOS before the JS bundle has finished hydrating. Without explicit splash screen management, the user sees a blank view for 1–3 seconds while fonts load and the bootstrap runs. Expo SDK 56 requires `expo-splash-screen` to control this lifecycle.

## Decision

Install `expo-splash-screen` and implement the standard Expo pattern:
1. Call `SplashScreen.preventAutoHideAsync()` at module level in `App.tsx` (before the component renders).
2. Inside the `App` component, call `SplashScreen.hideAsync()` after fonts are loaded (`fontsLoaded || fontError`).
3. Configure `app.json` with `splash.image: ./assets/splash-icon.png`, `splash.resizeMode: contain`, `splash.backgroundColor: #0A2342`, and mirror under `ios.splash`.

## Alternatives Considered

### Alternative: Manual timeout dismiss
- **Description**: Call `SplashScreen.hideAsync()` after a fixed 2-second timeout regardless of font state.
- **Pros**: Simple, no dependency on font loading lifecycle.
- **Cons**: Shows blank screen if fonts load in < 2s; crashes if fonts fail. User sees unnecessary delay.
- **Why rejected**: Inferior UX and doesn't handle font failures gracefully.

### Alternative: No splash screen, use ActivityIndicator only
- **Description**: Remove the splash screen concept; show ActivityIndicator on dark background while loading.
- **Pros**: No extra package.
- **Cons**: iOS still shows a blank system view before JS hydrates. This is the root cause of the black screen — can't be fixed without `expo-splash-screen`.
- **Why rejected**: Does not solve the iOS black screen; `expo-splash-screen` is required.

## Consequences

### Positive
- Black screen eliminated: native splash appears immediately on app launch.
- Graceful degradation: if fonts fail, `fontError` triggers `hideAsync()` so the user is never stuck.
- App Store and Google Play screenshots show branded splash instead of black screen.

### Negative
- Adds one new dependency (`expo-splash-screen`).
- Must be called at module scope (outside React component) — slightly unconventional pattern.

### Risks
- If `hideAsync()` is never called (unhandled exception before it runs), splash stays indefinitely. Mitigated by placing call in `useEffect` with no dependencies.
